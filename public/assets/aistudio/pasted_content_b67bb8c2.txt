# Project Title: AI College Study Assistant Using LLM

## 1. Project Overview

Develop a complete, modern, and user-friendly web application called **AI College Study Assistant**. This application helps college students understand difficult subjects, prepare for examinations, summarize PDF notes, and practice multiple-choice questions (MCQs) using Artificial Intelligence and a Large Language Model (LLM).

The application should work like a personal AI tutor. Students can ask questions in natural language, upload their study materials in PDF format, and receive answers based on the uploaded documents.

The application must be fully functional, not just a static UI design.

## 2. Technologies to Use

Use the following technologies:

**Frontend:**

* HTML5
* CSS3
* JavaScript
* Bootstrap or custom responsive CSS

**Backend:**

* Python
* Flask

**AI and LLM:**

* An LLM API, such as the Google Gemini API, for answering questions and generating study materials.
* Use environment variables to store API keys securely.

**PDF Processing:**

* PyMuPDF or PyPDF for extracting text from PDF documents.

**Additional Technologies:**

* SQLite for storing user accounts and study history.
* Python dotenv for environment variable management.

Choose compatible library versions and provide a requirements.txt file.

## 4. LLM Integration

Integrate a real LLM API into the Flask backend.

The AI should follow these rules:

1. Answer questions using clear, simple English.
2. Prefer information from the student's uploaded notes when the question concerns those notes.
3. Do not invent information that is not present in the uploaded material.
4. If the answer cannot be found in the uploaded document, clearly state that the document does not contain enough information.
5. When appropriate, distinguish between information taken from the document and additional general knowledge.
6. Generate educational explanations, summaries, MCQs, and question-answer sets.
7. Maintain the context of the current conversation for relevant follow-up questions.
8. Avoid unnecessarily complicated technical language.
9. Do not claim that a generated answer is guaranteed to be correct.
10. Handle API failures and rate limits gracefully.

For a more advanced version, implement Retrieval-Augmented Generation (RAG).

RAG should:

* Extract text from uploaded PDFs.
* Split long documents into smaller chunks.
* Convert chunks into embeddings.
* Store embeddings in a suitable vector database, such as FAISS or ChromaDB.
* Retrieve the most relevant chunks when a student asks a question.
* Provide the retrieved content to the LLM as context.
* Generate answers grounded in the retrieved content.
* Show relevant page numbers or document references when available.

Keep the basic application functional even if the advanced RAG feature is not implemented initially.
